# 规格：人脉罗盘（Relationship Compass）MVP

> 领域术语遵循 [GLOSSARY.md](../../GLOSSARY.md)，架构决策遵循 [docs/adr/](../adr/)。

## Problem Statement

用户没有一个能"梳理人脉"的工具：联系人是散的、和每个人的亲疏程度没有记录、也记不清上次联系是什么时候。现有人脉资源无法被有效维护和利用。

需要一个 macOS 原生应用：管理导入的联系人，标记重要度，记录每次互动，并主动提醒"该联系谁了"，让关系维护变得可见、可追踪。

## Solution

一个单用户本地 macOS 应用"人脉罗盘"，构建方式为 Swift Package（命令行 `swift build`，无需 Xcode）。

- **联系人管理**：三栏式界面（侧边栏视图区 + 联系人列表 + 详情面板），支持增删改查、搜索。
- **重要度**：每个联系人标记为 重要 / 一般 / 普通 三档，是列表排序的第一依据。
- **互动记录**：每次真实联系（电话/微信/邮件/见面/其他）记一条带日期和备注的记录；"上次联系时间"由记录自动推导。
- **待联系提醒**：每个联系人按"上次联系时间 + 联系频率（每周/每月/每季/自定义，未设时按重要度默认）"计算是否逾期；侧边栏"待联系"区展示逾期联系人并计数。
- **CSV 导入**：按固定模板（姓名、公司、职位、电话、邮箱、备注、重要度、联系频率）批量导入。
- **假数据**：首次启动自动写入约 20 条真实感中文联系人及互动记录，其中约 8 人处于待联系状态，便于直接体验。

## User Stories

1. 作为用户，我想在首次启动时看到预置的假数据联系人，以便立刻体验功能而不用先录数据。
2. 作为用户，我想在侧边栏看到 全部 / 重要 / 待联系 三个视图区及各区联系人数量，以便快速切换浏览视角。
3. 作为用户，我想在"全部"视图看到所有联系人按 重要→一般→普通 排序、同级内最近联系的靠前，以便优先关注重要的联系人。
4. 作为用户，我想在"重要"视图只看到标记为重要的联系人，以便聚焦核心人脉。
5. 作为用户，我想在"待联系"视图看到所有逾期未联系的联系人（含从未联系过的），以便知道该主动联系谁。
6. 作为用户，我想在侧边栏"待联系"看到逾期数量的数字角标，以便不用点开就知道有多少人需要维护。
7. 作为用户，我想通过搜索框按 姓名/公司/职位 过滤联系人，以便快速定位某人。
8. 作为用户，我想在列表中看到每个联系人的姓名、公司/职位、上次联系时间和逾期状态，以便列表信息自足。
9. 作为用户，我想在列表中看到逾期联系人的"逾期 N 天"提示，以便直观感受紧迫程度。
10. 作为用户，我想点击某联系人进入详情页，以便查看和管理他的全部信息。
11. 作为用户，我想在详情页看到联系人的基本资料（公司、职位、电话、邮箱、备注），以便全面了解这个人。
12. 作为用户，我想在详情页随时调整联系人的重要度（重要/一般/普通），以便反映关系的最新判断。
13. 作为用户，我想在详情页设置联系人的联系频率（按重要度默认/每周/每月/每季/自定义天数），以便控制维护节奏。
14. 作为用户，我想在详情页看到"上次联系时间 + 频率 = 应联系时间 / 是否逾期"的状态说明，以便理解待联系是怎么算出来的。
15. 作为用户，我想在详情页看到该联系人的全部互动记录（时间、方式、备注），以便回顾关系历史。
16. 作为用户，我想为某个联系人添加一条互动记录（选择日期、方式、填备注），以便真实记录每次联系。
17. 作为用户，我想在添加互动记录后立刻看到"上次联系时间"和待联系状态随之更新，以便信息保持一致。
18. 作为用户，我想删除某条互动记录（需确认），以便修正误记。
19. 作为用户，我想新增一个联系人（填姓名及可选资料），以便录入新人脉。
20. 作为用户，我想编辑已有联系人的资料，以便资料保持最新。
21. 作为用户，我想删除某个联系人（需确认），以便清理无效人脉。
22. 作为用户，我想通过"导入 CSV"按钮选择文件批量导入联系人，以便把已有表格数据带进来。
23. 作为用户，我想在导入界面看到固定模板的列说明和示例行，以便按格式准备文件。
24. 作为用户，我想导入时 重要度（重要/一般/普通）和 联系频率（每周/每月/每季/留空=默认）被正确解析，以便导入后无需逐条补设。
25. 作为用户，我想导入完成后看到成功条数和被跳过的无效行数，以便知道导入结果。
26. 作为用户，我想电话和邮箱能以可点击方式（tel:/mailto:）打开，以便一键联系。
27. 作为用户，我想在未选中联系人时看到占位提示，以便界面不会空白。

## Implementation Decisions

- **技术栈**：SwiftUI + Codable JSON 存储（`ContactStore: ObservableObject`，`@Published contacts`，读写 Application Support 下 `contacts.json`），Swift Package 可执行目标，`platforms: .macOS(.v14)`。命令行 `swift build` / `swift run` 构建运行；应用启动时设置 `NSApp.setActivationPolicy(.regular)` 并激活窗口（存储选择见 ADR-0004，构建方式见 ADR-0001）。
- **界面结构**：`NavigationSplitView` 三栏 —— 侧边栏（SidebarSection：全部/重要/待联系，带计数）+ 列表栏（搜索 + 联系人行）+ 详情栏（资料、频率、互动记录、工具栏操作）。列表选中通过联系人 `id`（UUID）绑定。
- **数据模型**（Codable 结构体，见 ADR-0004）：
  - `Contact`：姓名、公司、职位、电话、邮箱、备注、重要度、联系间隔天数 `cadenceDays: Int?`（nil=按重要度默认）、创建时间、互动记录数组（删除联系人时一并删除）。
  - `Interaction`：日期、方式、备注、所属联系人。
  - 枚举：`ImportanceLevel`（重要/一般/普通，含 `sortOrder` 与 `defaultCadenceDays`）、`InteractionMethod`（电话/微信/邮件/见面/其他）、`CadenceOption`（按重要度默认/每周/每月/每季/自定义，映射 7/30/90 天）。
- **待联系推导（ADR-0002）**：`lastContactDate = 互动记录中最新日期`（不存储）；`dueDate = lastContactDate + effectiveCadenceDays`；`isDue = lastContactDate == nil 或 dueDate < 今天`（从未联系视为待联系）。删除互动记录会影响推导结果，因此删除互动需确认。
- **默认频率（未设置时）**：重要→每月(30)，一般→每季(90)，普通→每半年(180)。
- **列表排序**：先按重要度升序（重要→一般→普通），同级内无互动记录的排前，其次按上次联系时间倒序。
- **CSV 导入**：固定模板 8 列 `姓名,公司,职位,电话,邮箱,备注,重要度,联系频率`；解析器支持引号包裹字段与表头跳过；重要度接受 重要/一般/普通；频率接受 每周/每月/每季/留空；导入不产生互动记录（新导入联系人均为"从未联系"→ 进入待联系）。提供 模板列说明 + 示例行 + 导入结果反馈（成功条数/跳过行数）。
- **假数据种子**：首次启动检测存储为空时写入约 20 条中文联系人（6 重要 / 7 一般 / 7 普通），每人 1-4 条分布在过去 1-2 年的互动记录，使约 8 人处于待联系状态，覆盖三种重要度和自定义频率各一例。

## Testing Decisions

- **好测试的标准**：只测外部行为，不测实现细节。即给定"互动记录集合 + 频率/重要度"，断言推导出的 上次联系时间、是否待联系、逾期天数；给定 CSV 文本，断言解析出的联系人字段。
- **测试切入点（seam）**：新增测试 target，测试运行于 **内存数组 + 临时文件 ContactStore**（不触碰真实 Application Support），对领域推导逻辑（上次联系时间/待联系/排序）与 CSV 解析器做单元测试。这是全项目唯一的测试 seam，UI 层不做自动化测试。
- **被测模块**：
  1. 待联系推导逻辑（`Contact` 的 `lastContactDate` / `dueDate` / `isDue` / `dueLabel`，覆盖：从未联系、频率默认与自定义、逾期边界）
  2. CSV 解析器（模板解析、引号字段、表头跳过、无效行跳过、重要度/频率映射容错）
  3. `ContactStore` 持久化（空文件首次写入种子、再次加载不重复写入）
- **先行参照**：本项目为全新代码库，无既有测试；以 XCTest（`swift test`）建立第一个测试 target 为后续测试的样板。

## Out of Scope

- 分组/标签归类
- 联系人之间的关联网络（"A 认识 B"式图谱）
- 系统本地通知（待联系仅以 App 内视图 + 计数呈现）
- CSV 列映射界面（固定模板）
- 读取 macOS 系统通讯录（Contacts 授权）
- 正式 Xcode 工程 / 签名 / 上架 App Store
- 云同步、多人协作

## Further Notes

- 范围决策见 ADR-0003（无分组/网络/系统通知/列映射是用户主动选择的刻意边界，不要当作遗漏"补上"）。
- 领域术语（联系人/重要度/互动记录/上次联系时间/联系频率/待联系/CSV 导入）见 GLOSSARY.md。
- 运行方式：`swift run RelationshipCompass`。
